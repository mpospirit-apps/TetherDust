# 0.8.2 — 2026-09-13

## Upgrade notes for admins
- Run the migration: `docker compose exec backend python manage.py migrate`.
  It deletes the `SystemConfiguration` rows nothing reads any more
  (`codex_service_url`, `codex_api_service_url`, `claude_service_url`,
  `claude_api_service_url`, `mcp_base_url`, `max_row_limit`,
  `hot_reload_interval`).
- If you ever set **Codex Service URL** or **MCP Base URL** in Console →
  Settings, move those values into the environment before upgrading:
  `CODEX_SERVICE_URL` / `MCP_BASE_URL` in `docker-compose.yml`, or the agent's
  own **Service URL** field on its Console → Agents page. The stored values are
  dropped by the migration.
- Rebuild the frontend image:
  `docker compose build frontend && docker compose up -d frontend`.

## Changed
- Console → Settings → **Timeouts** (renamed from "General") now only carries
  the three settings that are actually honoured end to end: **Doc Gen
  Timeout**, **Doc Library Gen Timeout** and **Chart Gen Timeout**. The page
  subtitle follows, and the card now explains what the timeouts govern — one
  background generation job's wall clock, after which the run is cut off and
  marked failed — with each field carrying its scope and default. The four
  settings that were dead or half-wired are gone:
  - **Codex Service URL** only ever applied to Codex agents — the sibling keys
    for `codex_api`, `claude_code` and `claude_code_api` were read by the
    backend but had no field in the panel, so a Claude agent silently ignored it.
  - **MCP Base URL** was honoured when the chat consumer read MCP resources, but
    `engine/agents/mcp_filter.py` and `api/v1/chat.py` read `MCP_BASE_URL`
    straight from the environment — so it never moved the agent's actual MCP
    endpoint.
  - **Max Row Limit** was unreachable: `PermissionsMixin._get_max_row_limit`
    only consulted it when a user had no `UserProfile`, and a `post_save` signal
    creates one for every user. Real caps come from the user's Role.
  - **Hot Reload Interval** was never read from the database at all — the only
    consumer is `tdmcp`, a separate container that reads the
    `TETHERDUST_HOT_RELOAD_INTERVAL` env var.
- Gateway URLs now resolve as *agent's own `service_url` → env var*, with no
  `SystemConfiguration` step in between, in every place that builds one
  (`CodexAgent`, `ClaudeCodeAgent`, `ClaudeCodeApiAgent`, the abort path, the
  system-prompt sync, agent status, and the Codex token-sync task).
- `PermissionService`'s roleless row cap is now the named
  `DEFAULT_MAX_ROW_LIMIT` constant instead of a bare `100` in two places.
- Console → Settings → Email (SMTP): **Use TLS** is a switch rather than a
  checkbox, and shares a row with **Send Test Email**, which is now a
  `btn-secondary` (the cyan outline button used across the console) instead of
  a borderless ghost button that did not read as a button at all.
- Toggle switches read green when on (`--success`) rather than lime — lime
  reads as a warning colour, and green/grey is the convention for on/off. This
  is the shared switch, so every toggle in the console changes with it.

- Console → Settings → Email (SMTP): **Use TLS** is now a toggle switch rather
  than a checkbox, sharing the row with **Send Test Email**, which picks up the
  cyan outline treatment and paper-plane icon that Test buttons use elsewhere
  (e.g. the database form). The row uses a new `.control-row` — a row of
  controls inside a card body, as against `.form-actions`, which is a footer
  and draws a rule above itself.
- Toggle switches now read as lime (`--c-lime`) when on, matching the accent
  used across the rest of the app; they were the only thing still using
  `--c-green`. Applies to every toggle, not just this page.

## Fixed
- Report delivery emails logged the execution id with `%d` while the id is a
  `rex_…` ULID string, so every send — success and failure alike — emitted a
  `--- Logging error ---` traceback to stderr instead of the intended line. Both
  call sites now use `%s`. Verified the whole path end to end against a real
  SMTP server: config read and password decrypt, HTML body, CSV attachment and
  envelope all land correctly.
- Disabled buttons had no styling of their own, so an in-flight action (e.g.
  "Sending…") looked as clickable as an idle one. `.btn:disabled` now dims to
  55% with a `not-allowed` cursor and drops the hover lift.
- Number-input spinner arrows were near-invisible in the dark theme — dark
  glyphs on a dark field. Nothing declared `color-scheme`, so browsers painted
  every native control with the light scheme regardless of the theme. `:root`
  now declares `color-scheme: light` and `[data-theme="dark"]` overrides it to
  `dark`, which also brings scrollbars and date pickers in line.

## Added
- `tests/engines/test_email_delivery.py` drives `send_report_email` to the wire
  against a real in-process SMTP server, asserting the envelope, subject, HTML
  body and CSV attachment as an MTA would receive them — and that the
  send-confirmation log line formats, which is what the `%d`-vs-ULID bug broke.
