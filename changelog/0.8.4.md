# 0.8.4 — 2026-09-14

## Upgrade notes for admins
- Run the migration: `docker compose exec backend python backend/manage.py migrate`.
  It removes the role **Can view tethers** switch. Any role that had it **off**
  loses its tether shares first, so nobody gains access to a tether they
  couldn't see before. Share them again from the role or tether form if you
  want those users to see them.
- Rebuild the frontend image:
  `docker compose build frontend && docker compose up -d frontend`.
- Restart the backend and the Celery worker so they stop reading the removed
  field: `docker compose restart backend celery-worker`.

## Changed
- **Add Role** now has a collapsible **How it works** card, like the other
  Configuration forms. It covers the four steps: define the role, set its
  permissions, grant access, and assign it to users.
- The role form now uses the same numbered sections as the Configuration forms:
  **01 Identity & Status**, **02 Permissions**, **03 Data Access** (databases,
  documentations, codebases, reports, dashboards, tethers) and **04 Agent
  Tooling** (tools, prompts, MCP servers). Checkboxes for flags are now
  toggles, and each one says what it does.
- Each grant list is now its own panel. It shows a selected/total count, has
  **All** / **None** shortcuts, and scrolls when the list is long. Tools are
  grouped by category (Charts, Querying, Docs, …) in two columns. An empty list
  links to where you can add one.
- A grant that currently does nothing is tagged **Inactive**: an inactive
  database, documentation, codebase, report, dashboard or tether, a disabled tool
  or prompt, or one on an inactive MCP server.
- Turning on **Admin role** now shows what it overrides. Row limit and
  **Can chat** lock as not applied or always on. The access grants dim and are
  disabled, with a note that they're ignored. **Can manage users** can only be
  switched on for an admin role, since only staff reach user and role
  management.
- Reports, dashboards and tethers are shared with a role the same way as
  databases, documentations and codebases: tick them under **Data Access**.
  These are the same lists as **Allowed roles** on the report, dashboard and
  tether forms, so either side can change them. The separate
  **Can view tethers** switch is gone. A role sees Tethers once at least one
  active tether is shared with it, the same as reports and dashboards already
  worked.
- The roles API drops `can_view_tethers` and adds `allowed_reports`,
  `allowed_dashboards` and `allowed_tethers`. `GET /api/v1/admin/roles/grants/`
  adds `reports`, `dashboards` and `tethers` lists, returns `is_active` on every
  option, and returns `category_label` on tools. `/api/v1/auth/me/`
  still returns a `can_view_tethers` flag, now worked out from the shared
  tethers.
