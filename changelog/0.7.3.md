# 0.7.3 — 2026-07-28

## Upgrade notes for admins
- Rebuild the `frontend` container to pick up the Agents changes below, and
  run `python backend/manage.py migrate` on `backend` to apply the ordering
  change (no schema change, `AgentConfiguration.Meta.ordering` only).

## Changed
- The **Add Agent** integration-type picker now shows two option cards per
  row (matching **Add Codebase**) and drops the redundant secondary line
  under each section title and the "(API key)" suffix on individual card
  titles — the section heading already says "CLI Tool with API Key".
- Option cards (Add Agent picker), the Agents list table, and the Add/Edit
  Agent page title now show each type's official brand mark — Claude Code,
  Anthropic, Ollama, and OpenRouter via Simple Icons, and OpenAI's mark
  (Codex, OpenAI Platform, and custom OpenAI-compatible types) via the
  bundled PNG — each in its brand color (e.g. Claude Code's orange). Marks
  that are near-black in their official color (Anthropic, Ollama) invert to
  stay visible against the dark-theme card background; OpenAI's mark does
  the same since it's a black-on-white PNG.
- The Agents list now shows each agent's icon next to its name.
- The Agents list's Active column now shows a toggle switch (the same
  rectangular switch used for "Is active" fields elsewhere, e.g. Add
  Codebase) instead of an "ACTIVATE" button / "ACTIVE" badge. Switching an
  agent on activates it; the currently-active agent's switch is on and
  disabled, since there's no way to deactivate an agent without activating
  another one.
- Creating a Codex subscription agent now lands you back on its edit screen
  (with the "Sign in to ChatGPT" panel ready) instead of the agents list,
  removing the manual "find it, click Edit" step the device-code sign-in
  requires (it's scoped to an already-saved agent record).
- The Model field now shows a per-type placeholder and example model IDs
  (e.g. `gpt-5.4-codex` for Codex, `claude-sonnet-5` for Claude Code) instead
  of a bare input, since it's a free-text string with no dropdown to
  discover valid values from. Direct API types (OpenAI Platform, Claude
  Console, Ollama, OpenRouter, custom OpenAI-compatible) now say the field
  is required, since — unlike the CLI types — they have no default model to
  fall back to when it's left blank.
- The Ollama agent form now shows setup steps under the Base URL field
  (matching the SQLite file-picker hint on Add Database Connection):
  serve/pull the model with `ollama`, use `http://host.docker.internal:11434/v1`
  instead of `localhost` (the agent runs inside the `backend` container, not
  on the host), and match the exact tag from `ollama list`. The Base URL
  placeholder is now Ollama-specific too.

## Fixed
- The Agents list no longer pulls the active agent to the top; agents are
  now listed in creation order regardless of which one is active.
- Saving an Ollama agent no longer requires an API key. `OllamaAgent` was
  already marked as not needing one (a self-hosted Ollama takes no auth),
  but the admin API's validation built its "required" set from every Direct
  API type without excluding Ollama, so the form demanded a key it never
  used.
