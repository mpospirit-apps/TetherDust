# 0.7.4 — 2026-07-29

## Upgrade notes for admins
- Rebuild the `frontend` container to pick up the changes below; no
  migration needed (`AGENT_TYPE_CATEGORIES` label change only).

## Changed
- A session that newly appears in the chat sidebar (a new chat's first
  entry, or an existing one bumped in after a reply) now slides/fades in
  instead of just popping into place — reuses the `history-in` keyframe
  already defined for this in `modules/chat.css`, previously unused.
- The **Add Agent** integration-type picker now labels the CLI-backed
  categories "Harness with Auth Token" / "Harness with API Key" instead of
  "CLI Tool with Auth Token" / "CLI Tool with API Key".
- The Add Agent picker now has a "Not finding what you're looking for?"
  section with a **Request an agent method** card linking to a new GitHub
  issue template (`.github/ISSUE_TEMPLATE/agent_support.md`), matching the
  "Request a database engine" card on Add Database Connection.

## Fixed
- Read-only prompt previews (the doc generation result preview and the
  agent System Prompt panel, both using `.doc-result-preview__content`) no
  longer show a dark grey background in light mode. The `rgba(0, 0, 0,
  0.15)` overlay was tuned for a dark card and read as a jarring grey box
  on the light theme's translucent card background; it's now a much
  lighter tint in light mode with the darker overlay kept for
  `[data-theme="dark"]`.
- The Active toggle for the currently-active agent in the Agents admin list
  no longer renders dimmed. It's still disabled (you can't deactivate an
  agent directly, only activate a different one), but a disabled *and
  checked* toggle should still read as "on" rather than looking greyed out
  like an unavailable control.
- A brand-new chat no longer requires a page refresh to appear in the left
  sidebar. The sidebar's session list only shows sessions with at least one
  message, but the only refetch trigger was `session_info`, which the
  backend sends on WebSocket connect — before the first message exists. The
  sidebar now also refetches when a turn actually finishes and gets
  persisted, which is the moment the new session (and its derived title)
  becomes visible to the list endpoint.
