# 0.8.5 — 2026-09-14

## Upgrade notes for admins
- No migrations and no new environment variables.
- Rebuild the frontend image:
  `docker compose build frontend && docker compose up -d frontend`.
- Restart the backend: `docker compose restart backend`.
- New and changed passwords set from **Console → Users** now have to pass
  Django's password rules: at least 8 characters, not all numbers, not a common
  password, and not too close to the username or email. Existing passwords
  aren't affected.
- Staff with **Can manage users** who aren't superusers can no longer edit,
  deactivate or delete superuser accounts. They can still open them read-only.

## Fixed
- **Anyone with user management could take over a superuser.** The users API
  let a non-superuser with **Can manage users** set a superuser's password,
  deactivate them or delete them. Only a superuser can now change or delete a
  superuser account.
- **You could lock yourself out.** Nothing stopped you deactivating your own
  account, or giving yourself a role that drops staff or user management.
  Both are now refused with a message explaining why. Moving yourself to
  another active admin role that can manage users still works.
- **Password rules were skipped.** `AUTH_PASSWORD_VALIDATORS` never ran for
  users created or edited in the console, so `1` was an accepted password.
- **A user could be created with no password.** The API accepted it and saved
  an account that could never sign in. A new user now needs a password.
- **Changing your own password signed you out** on the next request, because
  the session hash went stale. You now stay signed in.
- **A superuser's role couldn't be changed.** The API returned success but
  skipped saving the role for superusers. It's now saved, and superusers still
  keep staff whatever the role.
- After creating or editing a user, the API response showed their old role
  (a stale cached profile). It now shows the saved one.
- The Users list and the role pickers stopped at the first 50 entries (the API
  page size). They now load every page.

## Changed
- **Add User** has a collapsible **How it works** card, like the Configuration
  forms: create the account, assign a role, console access, and signing in.
- The user form uses numbered sections, **01 Account** and **02 Access**.
  - A **Confirm password** field catches typos, and the password rules are
    spelled out under the field.
  - The role is a styled picker. Below it, a summary shows what the role
    gives: chat, row limit, and how many databases, documentations,
    codebases, reports, dashboards, tethers, tools, prompts and MCP servers.
    It also warns when the user would have no role or an inactive role, and
    says when a superuser's role doesn't limit them.
  - **Is active** is a toggle that explains it blocks sign-in without
    deleting the account.
  - Editing shows when the user joined and last signed in. On your own
    account, the toggle is locked and the role field says what you can
    change.
- The Users list shows an avatar, email, a **You** badge, and the role as a
  link, tagged if it's inactive. Other changes:
  - An **Access** column shows Superuser, Admin, Member or No access.
  - A **Last Sign-in** column.
  - An **Active** toggle.
  - Deleting asks for confirmation in a dialog instead of the browser prompt.
  - Your own account has no Delete button or Active toggle.
  - A superuser shows as **View** for non-superusers.
- Staff without **Can manage users** now see an explanation on the Users page
  instead of "Failed to load users."
- The users API returns `last_login` and `role_is_active`.
