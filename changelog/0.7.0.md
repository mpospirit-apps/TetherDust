# 0.7.0 — 2026-07-21

## Upgrade notes for admins
- No migrations or new env vars. Semantic doc search reuses the existing `ccc`
  service (`CCC_SERVICE_URL`, already wired into the `mcp` and `celery-worker`
  containers). If `ccc` is not configured, `search_docs` transparently falls
  back to keyword search.
- Doc sources are indexed lazily: run **Reindex** on a documentation source
  (Console → Documentation), wait for the periodic resync (every 6 hours), or
  generate docs with AI to build the semantic index the first time.
- Rebuild the `codex`/`codex-api` and `frontend` containers to pick up the
  Codex shell-tool hardening and the Add Agent overview.

## Added
- Semantic (embeddings-based) search for the `search_docs` MCP tool, powered by
  the `ccc` service — one index per documentation source folder, mirroring
  `search_codebase`. Results are score-ranked and access-filtered to the folders
  the role is allowed to see.
- `Reindex` action on the Documentation admin page and a `POST
  /api/v1/admin/docsources/{id}/reindex/` endpoint.
- `resync_doc_sources` Celery beat task (every 6 hours) plus automatic reindex
  after AI documentation generation.

## Changed
- `search_docs` now uses semantic search when `ccc` is configured, falling back
  to the previous in-process keyword search otherwise.
- Standardized the built-in MCP tool descriptions so similar tools share the
  same wording. The `list_*` tools (databases, tables, codebases, dashboards,
  reports, tethers) now follow one template — "List all X available to you. Use
  this to discover which X exist before <action> them with <tool>. Returns each
  X's <fields>." — and the paired `get_*` detail tools use a consistent "Use
  list_X first to discover available X." discovery sentence.
- Codex agents now run with the built-in shell tool disabled
  (`features.shell_tool=false`), the closest Codex equivalent to Claude Code's
  MCP-only tool scoping. The agent can no longer read container files or run
  shell commands — data and artifact access still flow through the MCP tools
  (invoked by the Codex engine, not the shell). The read-only sandbox remains as
  defense-in-depth for any built-in without an individual disable switch.
- The **Add Agent** form now shows a collapsible "How it works" overview whose
  steps adapt to the selected integration method (Codex subscription device
  login, Claude Code OAuth token, API-key CLI, or Direct API), matching the
  other "Add …" wizards.
- Agent tool access is now defined per *surface* via a code-level registry
  (`engine.agent_surfaces`). Every surface — main chat, the chart-edit panel,
  and the doc / dashboard / tether generation flows — is limited to a curated
  built-in tool set: read tools are shared broadly, while **write tools are
  surface-exclusive** (only doc gen calls `create_documentation`, only dashboard
  gen calls `create_dashboard`/`add_chart`, only tether gen calls
  `save_tether_graph`, only the chart-edit panel calls `update_chart`). Main
  chat is read-only. Previously each generation flow (and free-form chat) could
  call *every* enabled tool. Custom MCP server tools remain available on the
  interactive/generation surfaces (they pass through), and per-user
  `Role.allowed_tools` still applies to chat on top (effective = surface
  allow-list ∩ role grants).
- Each built-in MCP tool card (Console → MCP Servers → Built-in) shows a cluster
  of surface icons on its title row — one per agent surface, lit when the tool
  is callable there and muted when not, with a hover tooltip and a decoding
  legend. The matrix is derived from the same registry, so it stays in sync with
  what each surface can actually call.
