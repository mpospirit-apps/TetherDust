# 0.7.5 — 2026-07-30

## Upgrade notes for admins
- Rebuild the `frontend` container to pick up the changes below; no
  migration needed.

## Changed
- The Reports admin list's "Status" column is now "Active" and uses the
  same toggle control as the Agents admin list instead of an ACTIVE/INACTIVE
  badge, so toggling a report on/off matches the pattern used elsewhere.
- Removed the redundant Activate/Deactivate button from the Reports admin
  list's Actions column now that the toggle in the Active column covers it.
- Clicking **Run** on a report in the admin list no longer navigates away.
  It now shows an inline status message under the row — matching the
  connection-test flash on the Databases admin list — with a link to the
  run's results on success, and the error message on failure (either a
  failed execution or a failed request).
- Added a global `a` style (`frontend/src/styles/modules/base.css`) — accent
  color, no underline until hover — so plain links like the new "View
  results" link read consistently across the app instead of falling back to
  the browser's default blue. More specific selectors (buttons styled as
  links, nav links, etc.) still take precedence.
- The Edit Report form now uses the same numbered step-by-step section
  layout (Identity & Status / Configuration / Optional Configurations) as
  the New Report form, instead of a plain two-card layout that grouped
  scheduling/delivery/access into the Configuration card.
- The Report form's Database, Schedule, and Delivery fields now use the
  app's `CustomSelect` (matching the styled dropdown used for e.g. the Doc
  Source Type field) instead of a native `<select>`.
- Reworked the Report form's layout: the third step (renamed **Schedule &
  Delivery**, was "Optional Configurations") now sits in the left column
  below **Identity & Status**, at the same width as the other cards,
  instead of spanning the full width. **Configuration** (now alone in the
  right column) stretches to match that column's height, and the
  **Preview (10 rows)** button — moved out of the page header to sit right
  under the SQL query field, right-aligned with a tighter top margin —
  renders its results inline in that same card instead of navigating away
  or appearing in a separate full-width card below the form.
- The Preview button now uses a new `.btn-warning` style (solid lime
  background, white text) instead of the outlined cyan `.btn-secondary`, to
  visually distinguish it from Save/Cancel while still reading as a filled
  call-to-action like `.btn-primary`.
- Relabeled the Report form's two right-of-Identity steps: the SQL-editing
  step (right column) is now "Query" and shows as step 3; the
  scheduling/delivery/access step (left column, below Identity & Status) is
  now "Configuration" and shows as step 2 — same card positions as before,
  just swapped numbers and names.
- **Preview (10 rows)** is now available on the New Report page, not just
  Edit. Since a new report has no id yet to run `/reports/{id}/preview/`
  against, added a new `POST /api/v1/admin/reports/preview_query/` endpoint
  that validates and runs an ad-hoc `{database, sql_query}` pair with the
  same row cap, without persisting a `ReportDefinition` or
  `ReportExecution` — the button is disabled until both a database and a
  query are entered. Because that preview isn't a persisted execution, its
  result table hides the CSV/Excel/Email actions (`ReportResultTable` grew
  a `downloadable` prop for this); the Edit page's preview is still a real
  persisted execution, so those actions keep working there.

## Fixed
- Report **Preview (10 rows)** against a SQL Server (`mssql`) connection no
  longer fails. The preview row cap wrapped every query in `SELECT * FROM
  (...) LIMIT n`, but T-SQL has no `LIMIT` clause; SQL Server now gets
  `SELECT TOP n * FROM (...)` instead, matching the engine-aware limit
  already used by the `query_database` MCP tool.
- A wide preview result table, or a long unbroken error line, inside the
  Report form's Query card no longer stretches that card wider than the
  Identity & Status / Configuration column next to it. `.wizard-section`
  and `.card` are grid/flex items that default to a content-fitting
  min-width, which overrides a nested `overflow-x: auto` container; added
  `min-width: 0` on the `.form-split` grid items (`forms.css`) so the grid
  track's width wins and the table/text scroll or wrap inside the card
  instead.
- Preview error messages (in the Report form's Query card) now use the same
  `.flash.flash-error` styling as the Reports admin list's Run-failure
  message, instead of a separate ad-hoc `<pre>` block. `.flash` gained
  `white-space: pre-wrap` + `overflow-wrap: break-word` so multi-line SQL
  errors still keep their line breaks while wrapping instead of needing
  horizontal scroll.
- Hovering any interactive `<a>`-based element app-wide (buttons styled as
  links like Cancel/Save, nav links, sidebar items, etc.) no longer gained
  a stray underline. The global `a:hover` rule added earlier this release
  has higher specificity than a single class (element + pseudo-class beats
  one class), so it was winning over those elements' own hover styles,
  none of which had previously needed to reassert `text-decoration: none`
  on hover. Scoped both the base `a` and `a:hover` rules to
  `a:not([class])` so they only apply to plain, unclassed content links
  (like "View results →") and leave every classed interactive element's
  existing hover behavior alone.
